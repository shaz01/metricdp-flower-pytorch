Client inference attack: two clear trends

Follow-up on the earlier attack-AUC-vs-accuracy report. Two questions, one plot per dataset each, built only from committed run data.

How to read every chart: Attack AUC measures how well an attacker can tell whether a client took part in training, after letting the attacker pick the more revealing direction. 50% = pure guessing (safe); 100% = attacker always right (unsafe). Model accuracy is plain test accuracy: higher is better.

1 · More clients → harder attack

Actual CIFAR-10 client-removal sweep, non-IID, one seed, same protocol at every client count. Red is vanilla FL (no privacy mechanism) — the case the trend is clearest for. The gray band is the range covered by Global-DP and Metric-privacy at the same client count, shown only as supporting context.

Vanilla FL Global-DP & Metric-privacy (range) 50% = random guess
Caveat: this exact test (several client counts, everything else fixed) has only been run on CIFAR-10 so far. We don't yet know if the same drop happens on our other datasets — that's the natural next experiment, not an established fact yet.

2 · More noise → harder attack, but a real accuracy cost

First, a full noise sweep on CIFAR-10 (48 clients, non-IID) so the trade-off is visible as noise actually increases. Then one vanilla-vs-DP comparison point each on four other datasets, to check the same direction holds elsewhere.

The size of the accuracy cost varies a lot by dataset in this data — small on EuroSAT and Fashion-MNIST, large on CIFAR-100 — so "noise lowers the attack" looks solid here, but "at a very heavy cost" isn't true everywhere we've checked.
