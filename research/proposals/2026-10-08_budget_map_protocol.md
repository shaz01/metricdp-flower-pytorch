# Public-budget map for the frozen stacked constructor

Owner: "go straight with this plan" (larger-public check, then matched-strength noise-law comparison, then CNN/Flower port). Mapping experiment, no tuning: the stacked configuration frozen in `stacked_constructor_freeze.json` (for 32 public examples) is applied UNCHANGED at public budgets 32/128/512 per class-balanced set on the two fresh tasks (Fashion-MNIST train classes 4-7, MNIST digits 0-3). Because it is frozen at 32, a shrinking gain at larger budgets is an honest map, not a failed tuning; no budget-specific retuning is done or implied.

Roles (new seed, drawn per class from the full pool, asserted disjoint): three public sets of B/4 per class for B in (32,128,512) (nested within a set seed is not required; sets differ per budget), a 128/class selection set (public candidate/base selection only), private cohorts A/B of 512/class (label-stress, 8 clients each), 512/class held-out evaluation. Cells per task and budget: 3 public sets x 2 cohorts = 6. 512 noise draws. Base = strongest selection-frozen public model from the same 24 scratch + 4 refine + 24 public-step family as before; arm = frozen stacked noisy at q.55/.65/.80.

Reported per task, budget and risk: number of cells with gain > .001 CE over the strongest public control, mean/min/max gain, accuracy delta, public control CE. Descriptive map only: no pass/fail gate and no claim beyond the frozen construction on these tasks. The attack calibration depends only on cap and risk target, which are unchanged; the attack check is not repeated. Limits as in the stacked protocol; task pools were used in the stacked transfer (roles redrawn with a new seed, no choice ever made on them).
